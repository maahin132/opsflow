

\# OpsFlow API Documentation



\*\*Version:\*\* 1.0  

\*\*Last Updated:\*\* 2026-09-27  

\*\*Backend:\*\* Django + Django REST Framework  

\*\*Authentication:\*\* Django Session Authentication



\---



\## 1. Overview



OpsFlow provides REST APIs for user authentication, organization management, projects, tasks, task comments, and activity tracking.



\### Base URL



Local development:



```text

http://127.0.0.1:8000/api/

```



All request and response bodies use JSON unless otherwise specified.



\---



\## 2. Authentication



OpsFlow uses Django session-based authentication.



After a successful login, the server creates an authenticated session and returns a session cookie.



For authenticated requests, the frontend must preserve cookies. With Axios, configure:



```javascript

axios.defaults.withCredentials = true;

```



For unsafe HTTP methods (POST, PUT, PATCH, DELETE), include the CSRF token when required by Django's CSRF protection and the configured REST framework authentication.



JWT bearer tokens are not used by the current authentication implementation.



\### Authentication endpoints



| Method | Endpoint | Description |

|---|---|---|

| POST | `/api/auth/register/` | Register a user |

| POST | `/api/auth/login/` | Log in |

| POST | `/api/auth/logout/` | Log out |

| GET | `/api/auth/me/` | Get current user |



\### Register



`POST /api/auth/register/`



Request:



```json

{

&#x20; "username": "maahin",

&#x20; "email": "maahin@example.com",

&#x20; "first\_name": "Maahin",

&#x20; "last\_name": "Suthar",

&#x20; "password": "StrongPassword123",

&#x20; "password\_confirm": "StrongPassword123"

}

```



Password must contain at least 8 characters. Password confirmation must match.



Success: `201 Created`



```json

{

&#x20; "message": "Account created successfully.",

&#x20; "user": {

&#x20;   "id": 1,

&#x20;   "username": "maahin",

&#x20;   "email": "maahin@example.com",

&#x20;   "first\_name": "Maahin",

&#x20;   "last\_name": "Suthar",

&#x20;   "phone": "",

&#x20;   "avatar\_url": "",

&#x20;   "is\_active": true,

&#x20;   "date\_joined": "2026-09-27T10:00:00Z",

&#x20;   "updated\_at": "2026-09-27T10:00:00Z"

&#x20; }

}

```



The response fields above illustrate the serializer structure; actual IDs and timestamps are generated by the server.



\### Login



`POST /api/auth/login/`



Request:



```json

{

&#x20; "identifier": "maahin@example.com",

&#x20; "password": "StrongPassword123"

}

```



`identifier` accepts a username or email address.



Success: `200 OK`



```json

{

&#x20; "message": "Login successful.",

&#x20; "user": {

&#x20;   "id": 1,

&#x20;   "username": "maahin",

&#x20;   "email": "maahin@example.com",

&#x20;   "first\_name": "Maahin",

&#x20;   "last\_name": "Suthar",

&#x20;   "phone": "",

&#x20;   "avatar\_url": "",

&#x20;   "is\_active": true,

&#x20;   "date\_joined": "2026-09-27T10:00:00Z",

&#x20;   "updated\_at": "2026-09-27T10:00:00Z"

&#x20; }

}

```



The response is accompanied by the session cookie.



\### Logout



`POST /api/auth/logout/`



Requires authentication.



Success: `200 OK`



```json

{

&#x20; "message": "Logout successful."

}

```



\### Current user



`GET /api/auth/me/`



Requires authentication.



Returns the current user's serialized information.

\## 3. Organizations



Base endpoint: `/api/organizations/`



Organization records are scoped to organizations accessible to the authenticated user.



| Method | Endpoint | Description |

|---|---|---|

| GET | `/api/organizations/` | List accessible organizations |

| POST | `/api/organizations/` | Create organization |

| GET | `/api/organizations/{id}/` | Retrieve organization |

| PUT | `/api/organizations/{id}/` | Replace organization fields |

| PATCH | `/api/organizations/{id}/` | Partially update organization |

| DELETE | `/api/organizations/{id}/` | Delete organization |



\### Create organization



`POST /api/organizations/`



Request:



```json

{

&#x20; "name": "OpsFlow Workspace",

&#x20; "slug": "opsflow-workspace",

&#x20; "description": "Team project management workspace",

&#x20; "logo\_url": "https://example.com/logo.png"

}

```



On creation, the authenticated user is automatically assigned as the organization owner.



\### Organization fields



| Field | Type | Description |

|---|---|---|

| id | integer | Generated organization ID |

| name | string | Organization name, max 150 characters |

| slug | string | Unique slug, max 180 characters |

| description | string | Optional description |

| logo\_url | URL | Optional logo URL |

| owner | string | Owner email, read-only |

| member\_count | integer | Number of organization members |

| is\_active | boolean | Organization active state |

| created\_at | datetime | Creation timestamp |

| updated\_at | datetime | Last update timestamp |



Only the owner can update or delete an organization.

\## 4. Projects



Base endpoint: `/api/projects/`



| Method | Endpoint | Description |

|---|---|---|

| GET | `/api/projects/` | List projects |

| POST | `/api/projects/` | Create project |

| GET | `/api/projects/{id}/` | Retrieve project |

| PUT | `/api/projects/{id}/` | Replace project fields |

| PATCH | `/api/projects/{id}/` | Partially update project |

| DELETE | `/api/projects/{id}/` | Delete project |

| POST | `/api/projects/{id}/members/` | Add project member |

| DELETE | `/api/projects/{id}/members/{user\_id}/` | Remove project member |



\### Project list filters



Use the `organization` query parameter:



```text

GET /api/projects/?organization=1

```



\### Create project



`POST /api/projects/`



Request:



```json

{

&#x20; "organization\_id": 1,

&#x20; "name": "Website Development",

&#x20; "description": "Build the company website",

&#x20; "code": "WEB",

&#x20; "status": "PLANNING",

&#x20; "priority": "HIGH",

&#x20; "start\_date": "2026-09-27",

&#x20; "due\_date": "2026-12-31",

&#x20; "is\_archived": false

}

```



Organization owners, admins, and managers can create projects.



\### Project status values



\- `PLANNING`

\- `ACTIVE`

\- `ON\_HOLD`

\- `COMPLETED`

\- `CANCELLED`



\### Project priority values



\- `LOW`

\- `MEDIUM`

\- `HIGH`

\- `CRITICAL`



\### Project fields



The project serializer returns:



`id`, `organization\_name`, `name`, `description`, `code`, `status`, `priority`, `owner`, `owner\_email`, `start\_date`, `due\_date`, `is\_archived`, `members`, `created\_at`, `updated\_at`.



`organization\_id` is accepted for writing and is not included as a writable response field.



The `members` field contains project member information, including user ID, username, email, role, assignment information, and membership timestamps.



\### Add project member



`POST /api/projects/{id}/members/`



Request:



```json

{

&#x20; "user": 2,

&#x20; "role": "MEMBER"

}

```



Project roles:



\- `MANAGER`

\- `MEMBER`

\- `VIEWER`



The user must already belong to the project's organization.



Success: `201 Created`



Returns the serialized project membership.



\### Remove project member



`DELETE /api/projects/{id}/members/{user\_id}/`



Success: `200 OK`



```json

{

&#x20; "detail": "Project member removed successfully."

}

```



Project update, deletion, and member management require organization manager-level access (owner, admin, or manager).

\## 5. Tasks



Base endpoint: `/api/tasks/`



| Method | Endpoint | Description |

|---|---|---|

| GET | `/api/tasks/` | List tasks |

| POST | `/api/tasks/` | Create task |

| GET | `/api/tasks/{id}/` | Retrieve task |

| PUT | `/api/tasks/{id}/` | Replace task fields |

| PATCH | `/api/tasks/{id}/` | Partially update task |

| DELETE | `/api/tasks/{id}/` | Delete task |

| POST | `/api/tasks/{id}/assign/` | Assign task |

| POST | `/api/tasks/{id}/status/` | Update task status |



\### Task list filters



Supported query parameters:



| Parameter | Description |

|---|---|

| project | Filter by project ID |

| status | Filter by task status |

| priority | Filter by priority |

| assigned\_to | Filter by assigned user ID |



Example:



```text

GET /api/tasks/?project=1\&status=IN\_PROGRESS\&priority=HIGH

```



\### Create task



`POST /api/tasks/`



Request:



```json

{

&#x20; "project\_id": 1,

&#x20; "title": "Implement login page",

&#x20; "description": "Build the login interface",

&#x20; "code": "TASK-001",

&#x20; "status": "TODO",

&#x20; "priority": "HIGH",

&#x20; "assigned\_to": 2,

&#x20; "start\_date": "2026-09-27",

&#x20; "due\_date": "2026-10-15",

&#x20; "is\_archived": false

}

```



The authenticated user is automatically recorded as `created\_by`.



The assigned user must be a member of the project.



Only organization owners, admins, and managers can create tasks.



\### Task status values



\- `TODO`

\- `IN\_PROGRESS`

\- `IN\_REVIEW`

\- `DONE`

\- `BLOCKED`



\### Task priority values



\- `LOW`

\- `MEDIUM`

\- `HIGH`

\- `CRITICAL`



\### Task fields



The serializer returns:



`id`, `project\_name`, `title`, `description`, `code`, `status`, `priority`, `assigned\_to`, `assigned\_to\_email`, `created\_by`, `created\_by\_email`, `start\_date`, `due\_date`, `completed\_at`, `is\_archived`, `created\_at`, `updated\_at`.



`project\_id` is write-only.



When a task is marked `DONE`, the model sets `completed\_at`. When the task is moved out of `DONE`, the model clears `completed\_at`.



\### Assign task



`POST /api/tasks/{id}/assign/`



Request:



```json

{

&#x20; "user": 2

}

```



The user must be a member of the project. Only organization owners, admins, and managers can assign tasks.



Success: `200 OK`



Returns the updated task.



\### Update task status



`POST /api/tasks/{id}/status/`



Request:



```json

{

&#x20; "status": "IN\_PROGRESS"

}

```



Only organization managers or the assigned user can update task status.



Success: `200 OK`



Returns the updated task.

\## 6. Task Comments



Base endpoint:



`/api/tasks/{task\_id}/comments/`



| Method | Endpoint | Description |

|---|---|---|

| GET | `/api/tasks/{task\_id}/comments/` | List comments |

| POST | `/api/tasks/{task\_id}/comments/` | Create comment |



\### Create comment



`POST /api/tasks/{task\_id}/comments/`



Request:



```json

{

&#x20; "content": "The login page implementation is ready for review."

}

```



The server automatically sets the task and author from the URL and authenticated user.



Comment response fields:



`id`, `task`, `author`, `author\_name`, `content`, `created\_at`, `updated\_at`.



Only members of the active organization can access the task comments.

\## 7. Task Activity



Endpoint:



`GET /api/tasks/{task\_id}/activities/`



Returns the activity records associated with a task.



Activity response fields:



`id`, `task`, `actor`, `actor\_name`, `action`, `description`, `metadata`, `created\_at`.



The activity endpoint is read-only in the current URL configuration.

\## 8. Permissions and access control



OpsFlow uses organization membership to scope organization, project, and task access.



| Action | Required access |

|---|---|

| View organization | Organization owner or member |

| Update/delete organization | Organization owner |

| Create project | Organization owner, admin, or manager |

| Update/delete project | Organization owner, admin, or manager |

| Manage project members | Organization owner, admin, or manager |

| Create task | Organization owner, admin, or manager |

| Update/delete task | Organization owner, admin, or manager |

| Assign task | Organization owner, admin, or manager |

| Update task status | Organization manager or assigned user |

| Access comments/activity | Member of the active organization |



All authenticated endpoints require an authenticated session.

\## 9. Error responses



The following are examples of errors explicitly returned by the API views.



\### Invalid credentials



```json

{

&#x20; "non\_field\_errors": \[

&#x20;   "Invalid username/email or password."

&#x20; ]

}

```



\### Missing user ID



```json

{

&#x20; "detail": "User ID is required."

}

```



\### Invalid task status



```json

{

&#x20; "detail": "Invalid task status.",

&#x20; "valid\_statuses": \[

&#x20;   "TODO",

&#x20;   "IN\_PROGRESS",

&#x20;   "IN\_REVIEW",

&#x20;   "DONE",

&#x20;   "BLOCKED"

&#x20; ]

}

```



\### User not in project



```json

{

&#x20; "detail": "User must be a member of this project."

}

```



Other common HTTP statuses:



| Status | Meaning |

|---|---|

| 200 | Request successful |

| 201 | Resource created |

| 400 | Invalid request or validation error |

| 401 | Authentication required |

| 403 | Permission denied |

| 404 | Resource not found |



Exact error response formats may vary depending on Django REST Framework validation, authentication, and exception handling.

\## 10. Implementation notes



\- API routes are registered in Django URL configuration and DRF routers.

\- Authentication uses Django sessions.

\- Organization membership scopes project and task querysets.

\- Project and task date validation prevents a due date earlier than the start date.

\- The API uses database-generated IDs and timestamps.

\- No JWT endpoints, file-upload endpoints, or organization member-management endpoints are documented because they were not present in the inspected URL configuration.
